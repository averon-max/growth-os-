# Hyprlyx — гайд по проекту (что, где, как, и на чём уже спотыкались)

Вставь этот файл в новый чат первым сообщением: там всё, что нужно знать о проекте.

## 1. Что это

- **Hyprlyx** (hyprlyx.com) — SEO-воркспейс: ключевые слова, Keyword Planner, позиции из Google Search Console,
  технический SEO-аудит, бэклинки, конкуренты, трафик и AI-краулеры из Cloudflare, аудитория из GA4,
  AI-писатель (бриф → черновик → одобрение человеком). Публикация в CMS — «скоро».
- Тарифы: Free (1 сайт, только бесплатные данные Google), Starter (7 дней бесплатно, с картой), Growth (+ AI-писатель),
  Autopilot (много сайтов). Цены берутся из Stripe, на сайте показываются те же.
- Сайт и продукт — на английском. Общение со мной — на русском.

## 2. Стек

- Next.js 16 (App Router; это НЕ тот Next, что в памяти моделей — см. `AGENTS.md`), React 19, TypeScript.
- Стили: CSS Modules. Файлы растут «слоями»: новые блоки дописываются в конец, часто с `!important`; побеждает последний.
- Prisma 7 + Postgres на Neon. **Схему Prisma не менять.**
- Stripe (отдельный live-аккаунт Hyprlyx), next-auth, OpenAI (писатель), DataForSEO (платные данные),
  Google Search Console / GA4 / Trends (бесплатно), Cloudflare (трафик и боты).
- Хостинг: Vercel, деплой из ветки `main` на GitHub (репозиторий приватный).

## 4. Как выкатываются изменения

1. Работаю в своей копии и присылаю **zip** с изменёнными файлами + одну команду.
2. Ты распаковываешь и пушишь (локально ветка `redesign`, на Vercel уходит в `main`):
   ```
   cd ~/growth-os && unzip -o ~/Downloads/hyprlyx-roundNN.zip && git add -A src public && git commit -m "..." && git push -q origin redesign:main
   ```
3. **Zip не умеет удалять файлы.** Если что-то удалено — в команде есть `git rm -q --ignore-unmatch <файлы>`.
4. Если в патче есть `docs/`, `content/`, `scripts/` или `package.json` — добавляй их в `git add` (`git add -A src public docs content scripts package.json`).
5. После деплоя проверяю живой сайт.

## 5. Локальная работа

- `npm run dev` → http://localhost:3000.
- Платные страницы (Backlinks, Competitors, Planner, Keywords) на localhost тратят DataForSEO. Запускать с `DATAFORSEO_OFFLINE=1`.
- `src/app/api/dev-login` — только локально, **никогда не коммитить**.
- `src/app/opengraph-image.tsx` лежит локально и не отслеживается — не трогать.
- Секреты только в Vercel/`.env`, никогда не вставлять в чат (вводить через `read -s`). Засвеченный ключ — сразу менять.

## 6. Данные и деньги

- DataForSEO платный: всё кэшируется, повторные запросы берут кэш. **Не менять тела платных запросов** без нужды —
  другой запрос = новый ключ кэша = повторная покупка.
- Бесплатное: Search Console, GA4, Cloudflare, Google Trends.
- На сайте нигде не писать про лимиты в день, бюджеты на пользователя и «цену в день».

## 7. Дизайн (сейчас)

- Фон **чистый чёрный `#000`**, строго, как Vercel/Linear. Карточки `#0a0a0a`, рамки 1px (`#1f1f1f`/`#262626`), радиус 12.
- Текст нейтральный серый: `#ededed` основной, `#a1a1a1` вторичный, `#8f8f8f`/`#6b6b6b` тише.
- **Никаких свечений**: ни пятен света, ни бликов на рамках, ни градиентных подложек, ни «AI glow».
- Скриншоты и карточки лежат на тихой сетке (линии 4% белого, шаг 32–48px) — это не свечение, это фон.
- Графики — исходная палитра по порядку: `#0090ff, #e93d82, #8e4ec6, #f76b15, #52a9ff, #ff6369, #a1a1a1`;
  статусы: хорошо `#30a46c`, внимание `#ffb224`, плохо `#e5484d`. Синий `#0090ff` — акцент, редко.
  Не сводить графики к одному синему (уже отклонено).
- Шрифты: Geist в интерфейсе, Newsreader (с засечками) для крупных заголовков маркетинга.
- Иконки только lucide и только с именами, которые уже есть в коде (lucide-react 1.x: неверное имя ломает сборку на Vercel).
  Логотип — картинка `/brand/mark-v2.webp`, не буква «h» шрифтом.
- Мобильная версия обязательна.

## 8. Скриншоты на сайте

- Только настоящие экраны приложения (демо-сайт `nova.example`) или точная пересборка в 2x **из реальных стилей**
  продукта (так сделаны Keywords, Content, Backlinks). Цифры можно подрисовать, но согласованно между собой.
- Конкуренты — выдуманные домены (`.example` и т. п.), **не размывать**. Вкладку Admin не показывать.
- Формат: WebP **без потерь**, 2x (3360×2100 для экрана 1680×1050). В коде `<Image unoptimized>` — Next не пережимает.
- Скрин не показывать шире половины его ширины в пикселях (иначе мыло на ретине). Никаких пар «два скрина рядом»:
  целый дашборд в половину ширины = нечитаемая каша.
- Перед заливкой смотреть каждый скрин: иконки, обрезанные соседние виджеты, остатки старого UI.

## 9. Тексты на сайте

- Подробно и по делу, без воды. Каждое утверждение = реальная функция. Нет функции — не писать.
- CMS — только «coming soon». AI-писатель — одна из функций, не главная.
- Тарифные карточки расписаны полностью (для кого, цена, кнопка, группы пунктов) — не урезать до пустых.

## 10. Блог (подробно — `content/blog/README.md`)

1. Новый чат → вставить `docs/BLOG_PROMPT.md` + тема → скопировать Markdown-блок.
2. `cd ~/growth-os && npm run post:paste -- --publish` — сохранит, проверит, закоммитит, запушит, пингует Bing/Yandex.
3. В Search Console: URL inspection → Request indexing.
- Проверить без публикации: `npm run post:paste`, потом `npm run post:publish -- <slug>`. Все посты: `npm run post:check`.
- Файл = URL. Опубликованный файл не переименовывать.

## 11. Частые ошибки (уже были — не повторять)

1. **Мыльные скрины**: WebP с потерями + пережатие Next (`quality=90`, 4:2:0) → текст размыт. Решение: lossless + `unoptimized`.
2. **Мелкие скрины парами**: два полных дашборда рядом → текст 4–5px, «мазня». Один экран на блок.
3. **Маленький исходник крупно**: скрин 1x, растянутый на всю ширину → мыло. Нужен 2x или показывать меньше.
4. **Выдуманные экраны и графики**, не похожие на приложение → отклонено («без вранья»).
5. **Свечения / пятна света / блики / градиенты** — отклонялись много раз. Только чёрный и тонкие рамки.
6. **Фиолетовые акценты в UI и «один синий» в графиках** — отклонено. Графики — исходная разноцветная палитра.
7. **Размытые конкуренты**, когда домены и так выдуманные, → выглядело сломанным.
8. **Не те иконки на скринах** (старая иконка, лишняя кнопка, буква вместо логотипа) — проверять каждую.
9. **Пустые карточки тарифов** после фильтрации пунктов → каждая карточка расписана полностью.
10. **Лимиты и «цена в день» на лендинге** — запрещено.
11. **Zip не удаляет файлы** → всегда `git rm` в команде.
12. **Новые папки не попали в коммит** (`docs/`, `content/`, `scripts/`) → добавлять их в `git add`.
13. **Неизвестное имя иконки lucide** → падает сборка на Vercel.
14. **Правка тела платного запроса** → новый ключ кэша → повторные траты DataForSEO.
15. **Платные страницы на localhost без `DATAFORSEO_OFFLINE=1`** → лишние траты.
16. **Стили «не применились»**: в модуле ниже есть правило с `!important` — новое писать в конец и тоже с `!important`, если надо.
17. **Две точки входа в настройки** (лого и ник вели в разные места) — сейчас одна; не плодить дубли.
18. **Скачки вкладок**: при смене вкладки должна меняться вся страница (сводка + графики + таблица), не только таблица.
19. **Лишние сущности**: не трогать схему Prisma, не делать разрушительных операций с базой, не удалять рабочие функции.
